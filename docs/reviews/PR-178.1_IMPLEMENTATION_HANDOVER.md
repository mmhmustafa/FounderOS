## 1. Executive result

Rows read as data again. The 50 accent-blue SSH buttons per page are gone
from Evidence and Configuration rows — every removed control has a named,
tested survivor in the same row's menu, including all five web-management
branches that were the inline block's one unique capability. The row menu
itself now opens where the operator can see it at every width (it was
clipped by its own scroll container, and opened entirely off-viewport at
375px), announces itself honestly as a native disclosure, and no longer
asserts store absences nobody checked. Policy stops rendering a dead bulk
workflow to viewers; selection finally reports "N of M selected" and the
bulk surface appears only while something is selected. No capability was
lost, no POST weakened, no nested form introduced, no bulk endpoint changed.

## 4. Menu semantic changes

`role="button"` and `aria-haspopup="menu"` deleted from the entity_menu
summary and the hand-rolled Changes menu summary — the only two action-menu
triggers. The summary now announces expanded/collapsed natively; the
row-aware accessible name (`"{label} for {name}"`) is kept. Deliberately
NOT added: menu/menuitem roles, aria-expanded by hand, roving tabindex,
arrow-key navigation — the list is ordinary links in a disclosure, and
arrow keys are the ARIA-menu expectation the adversarial review ruled out.
Pinned: no action-menu summary may carry a role override; no template may
carry `aria-haspopup=`.

## 5. Menu positioning implementation

Settled by hit test (not CSS reasoning): an absolutely positioned list
cannot escape `.table-scroll`, so on `toggle` (capture — it doesn't bubble)
JS measures the list, locks its width, and switches it to `position: fixed`
at viewport-clamped coordinates: right-aligned to the trigger, flipped
upward near the bottom edge, pinned inside the viewport when taller than
it. Any scroll — page or table container, capture-phase — CLOSES the menu
rather than tracking it; closing resets every inline style. The stylesheet
keeps `position: absolute`, so with JavaScript off the menu is exactly
today's baseline. `overflow-x` on table containers is untouched; nothing is
portalled; no popover attribute.

## 16. Availability-reason honesty fix

`has_evidence`/`has_configuration` are tri-state. Only an established
`False` (a caller that consulted the store) renders "no evidence records
are stored…"/"no configuration is held…"; a missing record id now states
only the addressing fact ("{name} has no canonical device record in this
scope, so its evidence cannot be opened from here"). Pinned both ways, plus
"a record id alone keeps the links available" so nothing that rendered live
before renders differently now. No new store work was added to obtain
flags — only facts pages already held are passed (Configuration's
version_count; Evidence's memory id).

## 23. Deviations from the adversarial architecture

1. **Lazy web resolution** (routes.py): the plan said "reuse the existing
   g._web_access request cache"; measurement showed the eager build
   resolved all ~865 devices for pages that render 50. The cache surface is
   unchanged but resolution is now lazy per device with an index pass —
   strictly less work, same duplicate-id semantics as the eager build.
2. **Evidence rows pass no store-level flags**: the plan's "pass them where
   cheaply available" met a fact that was cheap but WRONG in kind —
   `has_configuration` there is session-scoped. Passing it would have
   created exactly the false-assertion class this PR fixes, so Evidence
   rows pass only the memory id. Configuration rows pass their
   store-established flag as planned.
3. **The Evidence ≤101 target is met for viewers, not export-capable
   operators (152)** — the target was arithmetically mis-derived in both
   reviews (§7 above). The underlying commitment (inline SSH stops removed,
   one link + one trigger + checkbox per row) is delivered exactly.
4. **device.html now shows web actions twice** (inline block + its "More
   actions" menu): the one-builder rule means the menu everywhere carries
   web. The detail template itself is untouched; folding that duplication
   is the existing recorded residual for a detail-page PR.
