# PR-174.1 — Topology wheel-zoom regression — Root Cause Analysis & Implementation Plan

**Status:** investigation only — nothing implemented, nothing committed.
**Base:** `71de3a4` + uncommitted PR-174. All figures below are **measured in the running viewer**,
not inferred.

---

## Verdict first

**One line was deleted, and it is still deleted. The fix is to put it back.**

`wheelSensitivity: 0.15` was added deliberately in **PR-117 (`fe5c236`)** with a commit comment that
describes today's complaint word for word:

> *"The default wheel step is far too coarse over a range this wide: one notch jumped most of the
> way from readable to unreadable, so there was no way to sit at a chosen scale."*

It was removed in **`096f630` ("complete operational intelligence release through PR-162")**,
replaced by a comment asserting that Cytoscape's defaults are preferable. Cytoscape's default
`wheelSensitivity` is `1`, which over Atlas's 60× zoom range gives **2.512× per wheel notch**.

**PR-174 did not cause this and did not touch it.** Its diff contains no wheel handler, no
`wheelSensitivity`, and no zoom factor — only hint strings and a diagnostic that *reads* `cy.zoom()`.
What PR-174 changed is that the topology is now **visible**: before it, the canvas was blank with
every node 38,000 units off-screen, so no operator could observe wheel behaviour at all. The
regression has been live since `096f630`; PR-174 made it observable. That distinction matters,
because it means the wheel has been broken for longer than the symptom has been visible.

**There is exactly one zoom path.** No custom wheel handler exists anywhere in the viewer
(`grep` for `addEventListener('wheel'`, `onwheel`, `mousewheel`, `deltaY`, `deltaMode` → no matches),
and there is exactly **one** `cytoscape({…})` call and **zero** `cy.destroy()` calls. Most of the
brief's root-cause questions are therefore answered "no" by construction — see §2.

## 1. Exact regression mechanism

### 1.1 The formula, extracted from the bundled Cytoscape

`src/founderos_atlas/web/static/vendor/cytoscape.min.js`:

```js
s = deltaY / -250;                    // pixel mode
s *= renderer.wheelSensitivity;       // default 1 — the deleted line set this to 0.15
if (deltaMode === 1) { s *= 33; }     // line mode (Firefox)
level = cy.zoom() * Math.pow(10, s);  // base-10 exponential
cy.zoom({ level, renderedPosition: { x, y } });   // pointer-anchored
```

The base is **10**, not 2 or e. With `wheelSensitivity: 1` a standard 100-pixel notch produces
`10^0.4 = 2.512`.

### 1.2 Measured, live (synthetic `WheelEvent` at the canvas centre)

| Input | Now (default `1`) | With `0.15` | Button step (deliberate) |
|---|---|---|---|
| Chrome/Edge notch in (`deltaY −100`, mode 0) | **2.512×** | **1.148×** | 1.25× |
| Chrome/Edge notch out (`deltaY +100`, mode 0) | **0.398×** | **0.871×** | 0.80× |
| Firefox (`deltaY −3`, mode 1 / lines) | 2.489× | 1.147× | — |
| Trackpad (`deltaY −4`, mode 0) | 1.038× | 1.006× | — |
| `deltaMode 2` (page) | 1.009× — **inert** | 1.001× — **inert** | — |
| **Notches to cross the whole 0.05→3 range** | **4.5** | **29.6** | 18 presses |

**The wheel is currently twice as coarse as the `+`/`−` buttons**, whose own comment says
*"1.25 gives roughly a dozen presses across the whole range."* The fine control is coarser than the
stepped one — that is the regression in one sentence.

### 1.3 What is already correct (measured, not assumed)

| Property | Result |
|---|---|
| Handlers firing per wheel event | **exactly 1** (measured by capture-phase probe + zoom-ratio arithmetic) |
| `deltaMode 1` normalisation | **correct** — 2.489 vs 2.512, within 1% of pixel mode |
| Pointer-anchored zoom | **correct** — model-space drift under the cursor **0.126 units** |
| `preventDefault()` over the canvas | **yes** — page does not scroll while zooming |
| `preventDefault()` outside the canvas | **no** — normal page scrolling preserved, and zoom unchanged |
| Cytoscape instances | **1**, created once per document; `cy.destroy()` never called |
| min/max zoom | `MIN_ZOOM = 0.05`, `maxZoom: 3` — respected by Cytoscape's own clamp |

## 2. Root-cause questions, answered

| # | Question | Answer |
|---|---|---|
| 1 | Was a custom smoothing handler removed or bypassed? | **No custom handler ever existed.** What was removed is the one-line `wheelSensitivity: 0.15` option (`096f630`). |
| 2 | Is Cytoscape's native wheel zoom now active? | **Yes — and it always was.** It is the only path. |
| 3 | Are two handlers processing the same event? | **No.** Measured: exactly one zoom application per event. |
| 4 | Is `wheelSensitivity` reset during viewer recreation? | **No.** It is never set at all; the renderer default `1` applies from construction. |
| 5 | Are mouse and trackpad deltas treated identically? | **Yes — correctly so.** Both are `deltaMode 0`; the difference is delta magnitude (100 vs ~4), which the formula already handles proportionally. |
| 6 | Is `deltaMode` ignored? | **Mode 1 is handled correctly** (×33). **Mode 2 (page) is not handled** — a real but minor gap (§6, R3). |
| 7 | Is zoom multiplicative with an excessive factor? | **Yes — this is the defect.** `10^(Δ/−250)` with sensitivity 1 = 2.512× per notch. |
| 8 | Duplicate listeners? | **No.** One `cytoscape()` call, no re-instantiation, no manual wheel listeners. |
| 9 | Does discovery or layout switching recreate the instance? | **No.** `rebuildView()` replaces *elements*, not the instance. A scope change reloads the whole iframe document, so no listener can accumulate. |
| 10 | Do browsers differ materially? | **No, after the fix.** Chrome/Edge (mode 0) and Firefox (mode 1) land within 1% of each other. Safari/macOS trackpads emit small mode-0 deltas and are proportionally smooth. |

## 3. Recommended architecture — keep one path, restore one line

**Recommendation: restore `wheelSensitivity: 0.15` in the `cytoscape({…})` options. Do not add a
custom wheel handler.**

The brief says *"prefer using one authoritative zoom path"* and *"do not keep Cytoscape native wheel
zoom enabled while also applying a custom handler unless you prove they cannot both fire."* Restoring
the option satisfies both **by construction**: Cytoscape remains the single authoritative path, and
the question of double-firing cannot arise because no second handler exists.

Everything a custom handler would have to re-implement, Cytoscape already does correctly and
measurably: `deltaMode` normalisation, pointer anchoring (0.126-unit drift), min/max clamping,
`preventDefault` scoped to the canvas, and listener teardown tied to the instance.

### Alternative considered and rejected

**Custom handler + `userZoomingEnabled: false`.** This would allow a hard per-event clamp, but it
re-implements four behaviours that are currently correct, introduces a listener lifecycle to manage,
and creates the exact double-handling risk the brief warns about if `userZoomingEnabled` is ever
flipped back. It is more code, more risk, and more to keep in step — for one capability (spike
clamping) that measurement shows is not needed on real hardware (§6, R2).

**This is the simpler architecture, and it is simpler in the way that matters: it deletes a decision
rather than adding a subsystem.**

### Why `0.15` specifically

| Sensitivity | Per notch | Notches across full range | Assessment |
|---|---|---|---|
| 1.0 (today) | 2.512× | 4.5 | unusable |
| 0.30 | 1.32× | 15 | coarser than the `+` button |
| **0.15** | **1.148×** | **29.6** | finer than the button, ~30 notches — **recommended** |
| 0.10 | 1.096× | 44 | slow on a long zoom |

`0.15` was empirically tuned in PR-117 and is confirmed correct by measurement here. It makes the
wheel the *fine* control and the buttons the *stepped* control — the right relationship.

---

## 4. Event-normalisation strategy

No new normalisation code. Cytoscape's is correct for modes 0 and 1, as measured. The one gap —
`deltaMode 2` (page) being treated as pixels and therefore inert — is left **documented and
untreated** in this PR: no mainstream browser emits mode 2 for wheel events, and treating it would
require the custom-handler architecture rejected above. It is recorded in §6/R3 and in the test plan
as an explicitly known limitation rather than silently ignored.

---

## 5. Listener lifecycle strategy

Nothing to do, and that is the finding: one `cytoscape()` call per document, no `cy.destroy()`,
no manual wheel listeners, and `rebuildView()` swaps elements without touching the instance. A scope
or artifact change reloads the iframe document entirely. **Listener count cannot grow.** The test
plan pins this as a regression guard (§7, T8) so a future refactor that starts re-instantiating
Cytoscape is forced to confront it.

## 7. Test plan

The viewer is a self-contained HTML artifact; the existing suites
(`test_topology_visual_quality.py`, `test_topology_layout_physics.py`) already assert template
contracts and run extracted JS under node. PR-174.1 follows the same pattern —
`tests/test_topology_wheel_zoom.py`:

| # | Test | Guarantee |
|---|---|---|
| **T1** | The `cytoscape({…})` options contain `wheelSensitivity` with a value in `[0.05, 0.35]` | **the headline** — the deleted line cannot be deleted again |
| T2 | The comment beside it records the measured consequence, not a preference | R1/R5 — the removal in `096f630` happened because the comment argued taste |
| T3 | Compute `10^(−100/−250 × s)` from the value parsed **out of the template** and assert `1.05 ≤ factor ≤ 1.30` | one notch is a small, bounded change |
| T4 | Same computation for `deltaY = 300` (three notches) → assert < 1.6× total | repeated notches progress gradually |
| T5 | Trackpad delta (`deltaY 4`) → factor < 1.02 | trackpad smoothness |
| T6 | Firefox line mode (`deltaY 3, ×33`) within 5% of the pixel-mode notch | `deltaMode` normalisation holds |
| T7 | Template contains **no** `addEventListener('wheel'`/`onwheel`/`mousewheel` | single authoritative path — no double handling |
| T8 | Exactly one `cytoscape({` and zero `cy.destroy(` | listener count cannot grow on rebuild |
| T9 | `minZoom: MIN_ZOOM` / `maxZoom: 3` unchanged, `MIN_ZOOM === 0.05` | zoom limits untouched |
| T10 | `Reset view`, `Fit all`, `+`, `−`, Lens handlers still present and `STEP = 1.25` unchanged | no regression to the other controls |

T3–T6 parse the sensitivity **from the template** and evaluate Cytoscape's real formula, so they
verify the shipped value rather than a duplicated constant.

**Not automatable, deliberately:** pointer-anchor stability and per-event handler count were measured
live in this investigation (0.126 units; exactly 1) and are re-checked in §8 rather than simulated,
because a synthetic `WheelEvent` in a headless DOM proves less than a real device.

## 8. Browser-validation plan

Run the viewer with `?diag=1` (PR-174's development-mode invariants) so any coincidental layout or
camera fault surfaces during the same pass.

**Physical mouse wheel** — Chrome/Edge, then Firefox:
1. From the default landing zoom, **one notch in**: the readout must move ~86% → ~99%, i.e. a
   *visible but small* change. Not a jump to 200%+.
2. **Ten notches in, then ten out**: the readout must return to within a few percent of the start,
   and every intermediate value must be sittable.
3. **Hold the pointer over a specific device and zoom in five notches**: that device must stay under
   the cursor.
4. **Zoom out to the floor**: it must take ~15 notches to reach 5%, not 3.
5. Confirm the page behind the canvas does not scroll while zooming, and *does* scroll when the
   pointer is outside the canvas.

**Trackpad** (macOS Safari/Chrome, or a Windows precision touchpad):
6. A slow two-finger drag must zoom smoothly with no visible stepping.
7. A fast flick must not overshoot to a limit; momentum must decay naturally.
8. Pinch-to-zoom (`gesturechange`) must still work — Cytoscape handles it on a separate branch of
   the same handler, and it is unaffected by `wheelSensitivity`.

**Cross-check:** repeat step 1 in Firefox (line mode). The measured per-notch factors are within 1%
of Chrome, so any felt difference indicates something outside this fix.

**Regression sweep:** `Reset view`, `Fit all`, `+`, `−`, Lens, and a layout switch
(Logical ↔ Force) — each must behave exactly as before, with the zoom readout tracking.

## 10. Success criteria

1. **One notch changes zoom by ~15%**, measured: `1.05 ≤ factor ≤ 1.30`.
2. **~30 notches to cross the full 0.05→3 range** (today: 4.5).
3. The wheel is **finer than the `+`/`−` buttons** (1.148× vs 1.25×) — the fine control is finer.
4. Chrome (pixel) and Firefox (line) agree within 5%.
5. Trackpad deltas stay under 1.02× per event and feel continuous on real hardware.
6. Pointer-anchored zoom still holds the device under the cursor.
7. Exactly one handler processes each wheel event; the template contains no manual wheel listener.
8. Page scroll suppressed over the canvas, preserved outside it.
9. `Reset view`, `Fit all`, `+`, `−`, Lens and both layouts unchanged.
10. A test fails if `wheelSensitivity` is removed or set outside `[0.05, 0.35]`.
11. Full suite green (baseline **2,955 passed / 2 skipped / 901 subtests**).

## 11. APPROVED IMPLEMENTATION PLAN

**Step 1 — Restore the option.** In `cytoscape({…})`, after `maxZoom: 3`, reinstate
`wheelSensitivity: 0.15`.

**Step 2 — Write the comment as evidence, not opinion.** State the measured numbers: Cytoscape
applies `zoom × 10^(deltaY/−250 × sensitivity)`; at the default `1` a 100-pixel notch is **2.512×**
and the entire 0.05–3 range is **4.5 notches**, which is coarser than the `+`/`−` buttons' deliberate
1.25×. Name `096f630` as the commit that removed it and PR-117 as the one that added it, so the
history is one hop away for whoever reads it next. This comment is the actual deliverable of the PR —
the code change is one line, and the reason it stayed deleted for a whole release is that the
previous comment argued taste.

**Step 3 — Tests.** Add `tests/test_topology_wheel_zoom.py` with T1–T10 from §7, parsing the
sensitivity out of the template and evaluating Cytoscape's real formula so the *shipped* value is
what gets asserted.

**Step 4 — Browser validation.** Execute §8 on a physical wheel and, where available, a trackpad,
with `?diag=1` active. Record the observed readout progression (start → one notch → ten notches) in
the handover so the next person has measurements rather than adjectives.

**Step 5 — Full regression suite**, then a handover stating: the measured before/after factors, that
PR-174 neither caused nor touched this, the two documented limitations (spike clamping, `deltaMode 2`),
and the trackpad feel on real hardware.

**Non-goals:** do not add a wheel handler, do not clamp per-event deltas, do not touch the zoom
limits or the other controls, do not "simplify" the comment back into a preference, do not commit.
