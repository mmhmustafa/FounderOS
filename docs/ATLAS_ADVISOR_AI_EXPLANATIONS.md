# Advisor AI Explanations — INSIGHT (PR-166)

The first production consumer of [ORACLE](ATLAS_ORACLE_AI_PLATFORM.md). It adds one thing to the Advisor: an
optional panel that restates an answer Atlas has **already produced** for a different reader, or in a different
language.

**This is not a copilot.** Atlas remains responsible for discovery, evidence, correlation, routing and every
conclusion. ORACLE is responsible only for how those conclusions are worded.

## Flow

```
Operator asks  →  OIR routes  →  Atlas engine answers from evidence
                                      ↓
                        answer rendered immediately  ← the page is complete here
                                      ↓  (operator clicks "Explain", asynchronously)
                        POST /api/advisor/explain
                                      ↓
                   read the STORED answer (never re-run an engine)
                                      ↓
                   ORACLE: policy → feature flag → REDACTION → provider
                                      ↓
                        explanation rendered beneath the answer
```

The deterministic answer never waits on a model (Part 10). The panel is a separate, later request; if it never
returns, the page is exactly what Atlas produced.

## What the AI is given, and what it is not

**Given:** the stored answer's summary, the *labels and details* of the evidence Atlas cited, the checks Atlas ran,
the stated confidence, and — explicitly — what Atlas could **not** determine.

**Not given:** raw device output, configuration bodies, credentials, or anything ORACLE's redaction removes. The
model is asked to rephrase a conclusion, not to read evidence and form one.

Limitations are passed as their own prompt variable rather than being appended to the finding, because an unknown
that travels as a separate labelled field is far harder for a model to quietly drop than one buried in a paragraph.

## Audiences (Part 3)

| Audience | ORACLE capability | Reader described to the model |
|---|---|---|
| Network engineer | `plain-english` | Knows routing and configuration; wants precise operational detail |
| SOC analyst | `plain-english` | Cares about exposure, unexpected change, what to verify next |
| Operations | `plain-english` | On shift: what is affected, is it stable, what to escalate |
| Manager | `executive-summary` | Not a specialist; needs impact, risk, whether action is required |
| Executive | `executive-summary` | Needs situation, business impact and risk in plain sentences |

**The audience changes the reader, never the findings.** A test pins this literally: the finding block sent to the
model is byte-identical between audiences, and only the system prompt's reader description differs.

The executive prompt additionally forbids estimating cost, downtime or customer numbers — Atlas does not measure
them, so a summary that guessed at them would be inventing business impact.

## Translation (Part 4)

Choosing a language runs a **second** ORACLE call using the `translation` capability over the generated
explanation. Atlas's evidence is never translated — only the prose about it. The translation is audited and costed
separately, and if it fails, the untranslated explanation is kept rather than the whole thing being lost.

Offered: English, Hindi, Spanish, French, German, Portuguese, Japanese, Arabic.

## The panel (Parts 5–7)

Shown only when at least one explanation capability is enabled; otherwise the section is absent and the page is
byte-for-byte what PR-163 shipped. It provides: audience and language selectors, **Explain**, and — once an
explanation exists — **Copy**, **Download**, **Hide**. Switching audience or language re-explains only if an
explanation is already on screen.

Every explanation carries its provenance line: *generated by ORACLE from Atlas evidence*, provider, model, prompt
name and **version**, audience, whether it was translated, what redaction removed, and when it was generated. The
panel also states plainly that Atlas's evidence, confidence and limitations are unchanged by anything in it.

## Fallback (Part 8)

If ORACLE is disabled, unavailable, policy-denied, timing out, or its prompt fails, the panel shows one calm line:

> An AI explanation is not available right now. Atlas's answer above is complete on its own.

Operators never see provider errors, status codes or stack traces — those live in the AI audit ledger and
`/api/oracle/diagnostics`, where an administrator can act on them. The endpoint returns **200 with `ok: false`**
rather than an error status, so the browser has nothing to interpret and no error state to render.

## Audit (Part 9)

Inherited from ORACLE, unchanged: every explanation and every translation writes one ledger record with capability,
prompt version, provider, model, latency, tokens, estimated cost and redaction summary. **Explanation text is never
stored** — not in the ledger, not in the conversation, not in the audit trail. The panel's content lives only in the
browser until the operator copies or downloads it.

## Permissions and limits

`POST /api/advisor/explain` requires `investigate.run` — the same permission as asking a question — because an
explanation spends provider tokens, and merely being able to read the page must not be able to run up a bill. It is
rate-limited at 30/minute alongside the ask endpoints.

## Accessibility (Part 11)

The panel is a labelled region with an `aria-live` status line; the explanation body is focusable and receives focus
when an explanation arrives, so a screen-reader user is taken to the new content. All controls are real buttons and
selects with visible labels, reachable and operable by keyboard. Colours are design tokens only, so light, dark,
system and compact themes need no extra rules. Layout is responsive with no horizontal overflow.

## Known limitations

- **Explanations are not persisted.** Reloading the page clears the panel; re-explaining costs another call. Storing
  them would put un-auditable model text next to evidence, which PR-165 deliberately avoids.
- **Translation quality is the provider's.** Atlas does not verify a translation preserved the meaning, and a
  mistranslated uncertainty is a real risk — which is why the untranslated explanation is kept when translation
  fails, and why the provenance line always names the language.
- **No streaming.** The explanation appears when complete; a slow provider means a longer wait behind the calm
  status line (the deterministic answer is already on screen throughout).
- **One explanation at a time.** Switching audience replaces the current explanation rather than showing them side
  by side.
- **The model can still write a poor explanation.** The safety preamble, the passed-through limitations and the
  provenance line constrain and label it, but nothing here *verifies* the prose against the evidence. That is why
  Atlas's own answer is always displayed above it, and always first.
